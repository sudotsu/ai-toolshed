# Forward-Testing Protocol

Use this protocol after contract or validator changes.

## Inputs

Use two materially different validated `seo-teardown` v3 handoffs:

- A local-service site with entities, claims, conversions, profiles, reputation, and unavailable first-party/local-pack evidence.
- A public tool or content product with dynamic URLs, structured data, safety or regulated claims, privacy, canonicals, and user-generated representations.

Never modify the source handoffs or test projects.

## Neutral prompts

Give a fresh agent only:

- the skill path;
- teardown and disposable project paths;
- the allowed local-edit boundary;
- explicit prohibition on commit, push, deploy, publish, and external mutation;
- either a planning-only or implementation request.

Do not reveal expected findings, decisions, weaknesses, or evaluator conclusions.

## Required tests

1. Contract and negative validator fixtures.
2. Planning-only consumption of both handoffs.
3. At least one disposable implementation and convergence run that creates real local diffs.
4. Deterministic rerender and validation.
5. Critical review of preservation, authority, evidence-level discipline, convergence, and current-state claims.

Planning-only tests must preserve exact finding counts and every surface check, access row, material limitation, strength, and deliberate non-pursuit. They must create no product changes or ready states.

Disposable implementation tests must not commit, push, deploy, publish, or touch external systems. Require at least one real diff, focused verification, full-diff review, and a disposition for any implementation-induced defect.

## Evaluation rubric

Check whether the run:

- Used the exact installed upstream validator.
- Reconciled audited source, current source, and production without inventing alignment.
- Preserved pre-existing work.
- Revalidated every finding.
- Separated finding approval from external authority.
- Preserved provisional limitations and blocked evidence.
- Kept technical eligibility separate from indexing, ranking, citation, traffic, and outcomes.
- Rejected unauthorized external actions.
- Used high-risk rollout and rollback controls.
- Represented experiments honestly.
- Found and resolved or blocked convergence defects.
- Produced deterministic Markdown from canonical JSON.
- Avoided project-specific rules in the reusable skill.

## Failure-driven improvements

Record a failure before changing the reusable skill. Improve the contract or validator only for a general failure class. Never encode Omaha-, Keno-, or fixture-specific expected answers.

If fresh-agent execution is unavailable, disclose that limitation and distinguish schema tests from behavioral forward tests.
