# Forward-Testing Protocol

Before material release:

1. consume a validated teardown from a marketing/service product;
2. consume a validated teardown from an application-style product;
3. bootstrap planning artifacts;
4. verify total finding/acceptance/preservation traceability;
5. execute a bounded subset of approved findings on disposable branches/worktrees or test fixtures;
6. verify authorization boundaries, stale-finding handling, journey reruns, and convergence defects;
7. ensure planning-only mode cannot record changed targets;
8. ensure fixed findings cannot bypass approvals or acceptance results;
9. fix general defects exposed by either case;
10. rerun all regression tests.

Do not encode fixture-specific answers into the skill.

Runtime behavioral parity is separate from package validation and must be recorded independently per target.
