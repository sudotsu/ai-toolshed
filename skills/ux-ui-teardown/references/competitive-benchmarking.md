# Competitive benchmarking

Competitor comparison is a **calibration method**, not a separate design objective.

## Selecting competitors

Never guess a "top competitor" from model memory alone.

Use current, attributable measurements appropriate to the product:

- organic/local search visibility and overlap;
- estimated traffic or audience;
- review footprint and prominence;
- category rank or app-store position;
- market share, customer count, or usage data;
- credible third-party category lists;
- owner-supplied direct competitors, with separate evidence establishing benchmark relevance.

Record selection evidence and date/access time.

For a complete public/commercial audit where benchmarking is required, use at least two `measured` competitors. If only owner-supplied names or memory are available, the benchmark is provisional.

## Comparing without copying

Compare equivalent outcomes and patterns:

- how quickly the product orients a user;
- visual system and hierarchy;
- how much work is asked before value appears;
- navigation quality;
- form/question design;
- feedback, progress, and recovery;
- specificity/authenticity;
- mobile experience;
- trust and proof;
- distinctive strengths.

Extract the principle behind a competitor pattern. Do not reproduce their layout, copy, brand expression, illustrations, or distinctive interaction sequence.

## Better-than-competitor findings

Benchmarking must identify areas where the audited product is already stronger. Those become retained strengths so revision does not "normalize" the product toward competitors and erase differentiation.

## User sentiment

When public sentiment is available, it can support experience judgments. Separate:

- sentiment about the product/service itself;
- sentiment about the interface or flow;
- isolated anecdotes;
- repeated patterns across independent sources.

Do not convert a few comments into universal user truth.
